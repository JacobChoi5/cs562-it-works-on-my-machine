What is an EMF Query?

Standard SQL can't express cross-group comparisons in a single pass. Extended Multi-Feature (EMF) queries generalize GROUP BY to support n independent grouping variables, each filtered by its own σ (sigma) predicate.

Standard SQL Limitation

-- Needs 3 separate subqueries or joins:
-- NY sales vs NJ sales vs CT sales
SELECT cust,
  sum_NY, sum_NJ, sum_CT
FROM ... -- complex self-joins

EMF Query (this engine)

-- One clean declarative query:
S  = cust, 1_sum_quant,
     2_sum_quant, 3_sum_quant
n  = 3
V  = cust
σ₁ = 1.state='NY'
σ₂ = 2.state='NJ'
σ₃ = 3.state='CT'

The EMF Query Model

A query is defined by six components, analogous to extended relational algebra:

S — Select Attributes

Columns and computed aggregates to output (like SELECT in SQL).

n — Grouping Variable Count

How many independent groups (passes) the query requires.

V — Grouping Attributes

The dimensions to group by — shared across all n grouping variables.

F — Aggregate Vector

Aggregates tagged to a grouping variable: 1_sum_quant, 2_avg_price, …

σ — Sigma Conditions

One filter predicate per grouping variable. Controls which rows contribute to each group.

G — Having Condition

Post-aggregation filter on the final MF table (like SQL HAVING).

Code Generation

Produces a standalone generated_mf_query.py that can be run independently.

Parser — parser.py

Validates all six query components and builds a typed intermediate representation (IR) consumed by the rest of the pipeline.

Key validation rules

  • Aggregate tokens must match N_agg_attr or agg_N_attr
  • σ group numbers must be in range [1..n]
  • σ can reference only previously computed aggregates (no forward refs)
  • All S aggregates must also appear in F
  • Exactly one σ condition per grouping variable
  • No duplicate entries in S, F, or V
# Aggregate token regex & parser
def _parse_agg(token):
    parts = token.split("_")
    if len(parts) != 3:
        return None
    if parts[0].isdigit():
        return int(parts[0]), parts[1], parts[2]
    if parts[1].isdigit():
        return int(parts[1]), parts[0], parts[2]
    return None

# σ forward-reference guard
if ref_group >= current_group:
    error(f"σ references forward group")

MF Table — mf_structure.py

The in-memory MF table is a list of entry dicts — one row per distinct combination of grouping attributes V.

Entry structure

  • Group attributes (e.g. cust) — initialized from the first matching row
  • Aggregates — typed initial values: 0 for sum/count, None for min/max, {sum,count,value} dict for avg
{ "cust": None, "1_sum_quant": 0, "2_sum_quant": 0, "3_sum_quant": 0 }

Lookup strategy

Linear scan keyed on a tuple of grouping attribute values — simple, correct, and sufficient for classroom-scale sales data.

def lookup_mf_entry(table, row, attrs):
    key = build_group_key(row, attrs)
    return next(
        (i for i, e in enumerate(table)
         if build_group_key(e, attrs) == key),
        -1
    )

Query Execution — mf_query.py

The EMF algorithm runs n + 1 passes over the sales rows.

Scan 0 — Populate MF table

Insert one entry per distinct V-combination seen in the entire table.

Scans 1 … n — Aggregate per group

For each grouping variable g, scan every row. If the row's MF entry exists and passes σ_g, update all aggregates tagged to group g.

Final filter — Apply G (HAVING)

Keep only entries satisfying the G predicate; project to S columns; sort by V.

# Scan 0
for row in rows:
    if lookup(table, row, V) == -1:
        add_mf_entry(table, row, V)

# Scans 1..n
for g in range(1, n+1):
    sigma = get_sigma(g)
    aggs  = [a for a in F if a["group"]==g]
    for row in rows:
        pos = lookup(table, row, V)
        if pos != -1 and row_matches_sigma(...):
            for item in aggs:
                _update_agg(table[pos], item, row)

# G filter + project
results = [project(e) for e in table
           if entry_matches_g(e, G)]

Code Generation — generator.py

After executing the query in-process, the engine emits three standalone Python files as output artifacts.

generated_mf_struct.py

The MF entry template and empty table definition — the schema for this specific query.

generated_simple_query.py

A hardcoded warmup query from the project handout: single-pass GROUP BY over sales.

generated_mf_query.py

A full standalone EMF query program embedding the parsed query dict. Runnable independently via python3 -m generated.generated_mf_query.

Each file is written to _generated.py first, validated by running it with subprocess.run(["python", "_generated.py"]), then saved to its final path. This acts as a compile-time sanity check.

Example: 3-Group Sales Query

Find total sales quantity per customer, broken out by state: NY vs NJ vs CT — in a single EMF query.

# query.txt
SELECT ATTRIBUTE(S):
  cust, 1_sum_quant, 2_sum_quant, 3_sum_quant

NUMBER OF GROUPING VARIABLES(n):
  3

GROUPING ATTRIBUTES(V):
  cust

F-VECT([F]):
  1_sum_quant, 2_sum_quant, 3_sum_quant

SELECT CONDITION-VECT([sigma]):
  1.state='NY'
  2.state='NJ'
  3.state='CT'

HAVING_CONDITION(G):
  none

What this computes

Equivalent to three self-joins of sales — but expressed as one declarative query and executed in 4 passes (scan 0 + 3 sigma scans).

SELECT cust, SUM(quant) FILTER (WHERE state='NY'), SUM(quant) FILTER (WHERE state='NJ'), SUM(quant) FILTER (WHERE state='CT') FROM sales GROUP BY cust

Run: python3 main.py --file query.txt

Summary

What was built

  • Full EMF query parser with strict validation and typed IR
  • In-memory MF table engine with n+1 pass execution
  • Code generator — queries become runnable Python programs
  • 3 input modes: file, interactive, CLI args
  • PostgreSQL backend via sql.py + psycopg2

Design highlights

  • Forward-reference guard prevents invalid σ predicates
  • avg stored as {sum, count, value} to support incremental updates
  • Generated files are self-contained and independently runnable
  • Single public entry point: build_query_data() → clean IR for all downstream modules
